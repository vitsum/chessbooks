# Шахматные книги → интерактивные приложения

Конвейер, который превращает шахматную книгу в самодостаточный HTML-файл:
доска, варианты по главам, комментарии, оценки Stockfish и проводник по позициям.
Интернет при работе приложения не нужен — библиотеки, фигуры и данные вшиты в файл.

Основная сборка — **все три защиты в одном файле** `dist/chess-defences.html`:
вкладки книг сверху, а проводник ищет позицию сразу по всем книгам.

| id | книга | вариантов | ходов | комментариев |
|---|---|---|---|---|
| `alekhine` | А. Корнев, «Play the Alekhine Defence» (2019) | 50 | 1170 | 273 |
| `pirc` | В. Москаленко, «Защита Пирца-Уфимцева и Современная защита» (2016) | 62 | 1289 | 303 |
| `kid` | Э. Гуфельд, О. Стецко, «Искусство староиндийской защиты» (2017) | 31 | 621 | 119 |
| | **всего в объединённом файле** | **143** | **3080** | **695** |

## Быстрый старт

```bash
pip install chess            # python-chess
apt-get install -y stockfish # бинарник ложится в /usr/games/stockfish

python3 run.py build         # dist/chess-defences.html — все книги в одном файле
```

Полный цикл по одной книге:

```bash
python3 run.py gen   kid      # data/data_kid.json из src/_body_kid.py
python3 run.py eval  kid      # прогон Stockfish -> data/cp_kid.json  (~2 мин на книгу)
python3 run.py gen   kid      # ещё раз: подтягивает cp в data
python3 run.py build kid      # dist/kid-gufeld.html — только эта книга
python3 run.py check          # автопроверка на просмотры

python3 run.py all kid        # всё сразу
python3 run.py build all      # три отдельных файла + объединённый
```

`STOCKFISH=/path/to/stockfish` — если бинарник лежит в другом месте.

## Структура

```
run.py                 единственная точка входа: gen / eval / build / check / all
src/
  books.py             заголовки, короткие имена вкладок и имена выходных файлов
  _head.py             build() и add() — разбор ходов через python-chess
  _body_alekhine.py    ← ВСЁ СОДЕРЖИМОЕ КНИГИ: вызовы add(...) с ходами и комментариями
  _body_pirc.py
  _body_kid.py
  _tail_clean.py       постобработка: вехи оценок, подварианты, кликабельные ходы,
                       сортировка по главам, превью, запись data_<book>.json
  scan.py              распознавание последовательностей ходов внутри текста комментариев
  template.html        шаблон приложения (плейсхолдеры __TITLE__, __BOOKS__, __JQUERY__ и т.д.)
data/                  data_<book>.json — готовые варианты; cp_<book>.json — оценки движка
vendor/                jquery, chess.js, chessboard.js, 12 SVG-фигур Cburnett
dist/                  готовые приложения
docs/                  заметки
```

Шаблон один на все сборки: в `__BOOKS__` уезжает список книг
`[{id, short, h1, eyebrow, sub, credit, vars}]`. Если книга в списке одна —
вкладки и подсказка про цифровые клавиши сами прячутся, файл выглядит как раньше.

## Как добавить вариант

В `src/_body_<book>.py`:

```python
add("ид_варианта", ГЛАВА, "Заголовок", "³", "³ у чёрных чуть лучше",
 "e4 d6 d4 Nf6 Nc3 g6 f4 Bg7",          # ходы через пробел, SAN
 {"4.f4": "Комментарий к этому ходу.",   # ключ — номер и ход как их печатает движок
  "4...Bg7": "И к этому."})
```

Ключ комментария (`"4...Bg7"`) сверяется со списком, который генерирует python-chess.
Если промахнулся — `gen` падает и печатает **все** доступные ключи варианта: просто
скопируй нужный. Нелегальный ход тоже сразу валит сборку — это главная защита от
ошибок при переносе с бумаги.

Необязательные поля в конце файла книги:

* `EVALS = {"ид": {"9.Nxe5": "µ"}}` — вехи книжной оценки (символ в градуснике до
  появления движковых оценок).
* `SUBS  = {"ид": {"8...e5": [("подпись", "Nxe5 Nd4 Qd3", "after")]}}` — побочные линии,
  проигрываемые на доске; `"before"` = от позиции перед указанным ходом.

Кроме того, `scan.py` сам находит последовательности ходов **внутри текста** комментария,
проверяет их на легальность и делает кликабельными. Различает два вида: обычную линию
(ходы чередуются) и «расстановку» — план одной стороны, где ходы соперника пропускаются
через null-move.

## Что умеет приложение

* вкладки книг сверху, клавиши <kbd>1</kbd>…<kbd>9</kbd> — переключение между защитами;
* доска (chessboard.js + chess.js), развёрнутая со стороны чёрных, свайпы и стрелки;
* выбор варианта списком по главам + стрелки перехода между вариантами;
* комментарии с защитой от пропуска: вспышка, вибрация, счётчик и плашка
  «пропущено N — вернуться» (счётчик прочитанного свой у каждой книги);
* градусник Stockfish (глубина 16, посчитано заранее и вшито в файл);
* кликабельные побочные линии прямо в тексте комментариев;
* **проводник**: свободно двигаешь фигуры, приложение показывает книжные продолжения
  из этой позиции с числом вариантов и список совпадающих линий с переходом в них —
  **сразу по всем книгам**. После 1.e4 видно `Nf6 50` (Алехин), `d6 50` и `g6 9` (Пирц
  и Современная), после 1.d4 — староиндийские линии. Клик по совпадению перекидывает
  в нужную книгу и на нужный ход. Поиск по FEN, поэтому перестановки ходов ловятся сами.

## Известные ограничения и что делать дальше

* Книги Москаленко и Гуфельда — **сканы без текстового слоя**. Ходы брались из «Индекса
  вариантов» и прочитанных вручную страниц, комментарии — с прочитанных страниц.
  Охват: Москаленко ~27 страниц из 308, Гуфельд ~20 из 333. Корнев — с текстовым слоем,
  разобраны части 1–2 (главы 1–8 из 16).
* Полезно прогнать сканы через OCR с русским языком (`ocrmypdf -l rus+eng`) — тогда
  книгу можно искать по тексту и добирать комментарии массово.
* Не сделано: главы 9–16 у Корнева; части «Из практики романтиков наших дней»
  у Гуфельда; сами партии (миттельшпили) у Москаленко, кроме двух разобранных.
* `run.py check` ловит только грубые ошибки записи (резкое падение оценки). Тихие
  неточности — перепутанный порядок ходов при той же оценке — он не увидит.
  Три текущих срабатывания — не ошибки: это жертвы в разобранных партиях.
* Проводник ходит только по правилам; произвольную расстановку фигур он не умеет.
  Превращение пешки всегда в ферзя.
* PDF-книг в репозитории нет (объём и авторские права) — положи их рядом и укажи путь сам.
