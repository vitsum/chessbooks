# Шахматные книги → интерактивные приложения

Конвейер, который превращает шахматную книгу в самодостаточный HTML-файл:
доска, варианты по главам, комментарии, оценки Stockfish и проводник по позициям.
Интернет при работе приложения не нужен — библиотеки, фигуры и данные вшиты в файл.

Сборка одна: **все книги в одном файле** `dist/index.html` — вкладки книг сверху,
проводник и тренажёр работают сразу по всем книгам. Он же корень сайта.
Репертуар может быть и за чёрных, и за белых: поле `side` в `src/books.py` разворачивает
доску нужной стороной и определяет, за кого играет пользователь в тренажёре.

## Быстрый старт

```bash
pip install chess            # python-chess
apt-get install -y stockfish # бинарник ложится в /usr/games/stockfish

python3 run.py build         # dist/index.html — все книги в одном файле
```

Полный цикл по одной книге:

```bash
python3 run.py gen   kid      # data/data_kid.json из src/_body_kid.py
python3 run.py eval  kid      # прогон Stockfish -> data/cp_kid.json  (~2 мин на книгу)
python3 run.py gen   kid      # ещё раз: подтягивает cp в data
python3 run.py build          # пересобрать приложение
python3 run.py check          # автопроверка на просмотры

python3 run.py all kid        # всё сразу
```

`STOCKFISH=/path/to/stockfish` — если бинарник лежит в другом месте.

## Публикация на GitHub Pages

`dist/` в репозитории нет — его собирает GitHub Actions. Обновление сайта = `git push`:
push в `main` запускает [.github/workflows/pages.yml](.github/workflows/pages.yml),
тот делает `python run.py build` и публикует `dist/`. Сборке не нужны ни Stockfish,
ни python-chess — только стандартная библиотека, данные книг уже лежат в `data/`.

Пересобрать без коммита: вкладка **Actions → Публикация на GitHub Pages → Run workflow**.

Настройка один раз:

```bash
git remote add origin https://github.com/<аккаунт>/chessbooks.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Первый деплой поднимется через пару минут по адресу `https://<аккаунт>.github.io/chessbooks/`.

На сайте оказывается один файл — `index.html`, он же приложение.

## Структура

```
run.py                 единственная точка входа: gen / eval / build / check / all
src/
  books.py             заголовки книг и короткие имена вкладок
  _head.py             build() и add() — разбор ходов через python-chess
  _body_alekhine.py    ← ВСЁ СОДЕРЖИМОЕ КНИГИ: вызовы add(...) с ходами и комментариями
  _body_pirc.py
  _body_kid.py
  _tail_clean.py       постобработка: вехи оценок, подварианты, кликабельные ходы,
                       сортировка по главам, превью, флаг off (вне тренировки),
                       запись data_<book>.json
  scan.py              распознавание последовательностей ходов внутри текста комментариев
  pgn2body.py          PGN-книга -> _body_<id>.py (так сделана книга Бладгуда)
  template.html        шаблон приложения (плейсхолдеры __TITLE__, __BOOKS__, __JQUERY__ и т.д.)
data/                  data_<book>.json — готовые варианты; cp_<book>.json — оценки движка
vendor/                jquery, chess.js, chessboard.js, 12 SVG-фигур Cburnett
dist/                  готовые приложения (в гит не идут, собираются заново)
docs/                  заметки
.github/workflows/     сборка и публикация на GitHub Pages
```

В `__BOOKS__` уезжает список книг `[{id, short, h1, eyebrow, sub, credit, vars}]`.
Добавить четвёртую книгу — дописать её в `BOOKS` и положить `data_<id>.json`,
вкладка появится сама.

## Книга из PGN

Бладгуд пришёл не сканом, а базой партий: каждая запись PGN — вариант с авторскими
комментариями, вложенными вариациями и знаками. Разбирать такое глазами незачем:

```bash
python3 src/pgn2body.py books/tactical_grob.pgn > src/_body_bloodgood.py
```

Берутся только теоретические записи (тег `White` вида `Variation ...`); две с лишним
сотни партий целиком пропускаются. Знаки `!`/`?`/`!?` становятся пометками к ходу,
а вложенные вариации — сразу двумя вещами: проигрываемыми побочными линиями (`SUBS`)
и текстовым разбором в комментарии. Разбор в комментарии верстается блоками — по блоку
на альтернативу, с её первым ходом в заголовке и ссылкой на партию приглушённо:

```html
<div class="alts"><span class="cap">вместо Nf6</span>
  <div class="alt"><b>4…Qc7</b> 5.Nc3 Nf6 … <i>1-0 Grob–Chevalier 1964</i></div>
  <div class="alt"><b>4…Qb6</b> 5.Nc3 e5 … </div>
</div>
```

Без этого весь разбор сливался в один нечитаемый абзац: у Бладгуда в одном
комментарии бывает по четыре системы с полными партиями. Дальше файл живёт как
обычный `_body_*.py`, его можно править руками.

## Как добавить вариант

В `src/_body_<book>.py`:

```python
add("ид_варианта", ГЛАВА, "Заголовок", "³", "³ у чёрных чуть лучше",
 "e4 d6 d4 Nf6 Nc3 g6 f4 Bg7",          # ходы через пробел, SAN
 {"4.f4": "Комментарий к этому ходу.",   # ключ — номер и ход как их печатает движок
  "4...Bg7": "И к этому."})
```

Ключ комментария (`"4...Bg7"`) сверяется со списком, который генерирует python-chess.
Если промахнулся — `gen` падает и печатает **все** доступные ключи варианта: просто
скопируй нужный. Нелегальный ход тоже сразу валит сборку — это главная защита от
ошибок при переносе с бумаги.

Необязательные поля в конце файла книги:

* `EVALS = {"ид": {"9.Nxe5": "µ"}}` — вехи книжной оценки (символ в градуснике до
  появления движковых оценок).
* `SUBS  = {"ид": {"8...e5": [("подпись", "Nxe5 Nd4 Qd3", "after")]}}` — побочные линии,
  проигрываемые на доске; `"before"` = от позиции перед указанным ходом.

Кроме того, `scan.py` сам находит последовательности ходов **внутри текста** комментария,
проверяет их на легальность и делает кликабельными. Различает два вида: обычную линию
(ходы чередуются) и «расстановку» — план одной стороны, где ходы соперника пропускаются
через null-move.

## Что умеет приложение

* вкладки книг сверху, клавиши <kbd>1</kbd>…<kbd>9</kbd> — переключение между защитами;
* три режима: чтение варианта, проводник по позициям и тренажёр;
* доска (chessboard.js + chess.js), развёрнутая со стороны чёрных, свайпы и стрелки;
* выбор варианта списком по главам + стрелки перехода между вариантами;
* комментарии с защитой от пропуска: вспышка, вибрация, счётчик и плашка
  «пропущено N — вернуться» (счётчик прочитанного свой у каждой книги);
* градусник Stockfish (глубина 16, посчитано заранее и вшито в файл);
* кликабельные побочные линии прямо в тексте комментариев;
* **проводник**: свободно двигаешь фигуры, приложение показывает книжные продолжения
  из этой позиции с числом вариантов и список совпадающих линий с переходом в них —
  **сразу по всем книгам**. После 1.e4 видно `Nf6 50` (Алехин), `d6 50` и `g6 9` (Пирц
  и Современная), после 1.d4 — староиндийские линии. Клик по совпадению перекидывает
  в нужную книгу и на нужный ход. Поиск по FEN, поэтому перестановки ходов ловятся сами.
* **тренажёр** — см. ниже.

## Тренажёр

Кнопка «🎓 Тренажёр» или клавиша <kbd>T</kbd>. Приложение играет за белых по одному
из вариантов книги, ты отвечаешь за чёрных перетаскиванием фигур. Заголовок варианта
на время прогона скрыт — он открывается в конце.

**Развилки.** Из многих позиций книга даёт не один ответ (в Пирце таких развилок 20).
Если сыграть ход из другой линии — это не ошибка: фигура возвращается, а тренажёр
пишет «✓ ход правильный, он ведёт в вариант «…». Но сейчас мы тренируем другой».
Прогон остаётся на начатом варианте: иначе он растекался бы по всей книге.

Исходы хода:

| что сыграл | реакция | ошибка? |
|---|---|---|
| ход целевого варианта | идём дальше | нет |
| ход есть в книге, но в другом варианте | «✓ правильный, но тренируем другой», фигура назад | нет |
| ход по правилам, но в книге его нет | «✕ такого хода нет в репертуаре» | да |
| ход не по правилам | «так не сходить», фигура возвращается | нет |
| забрал ход назад | откат к прошлой развилке | нет |

Кнопка «Показать ход» играет книжный ответ за тебя и засчитывает ошибку,
«Не знаю, дальше» закрывает вариант как непройденный и берёт следующий.
«Открыть в книге» (клавиша <kbd>B</kbd>) в любой момент выходит из тренажёра прямо
на текущей позиции текущего варианта — прогон при этом не засчитывается ни как
пройденный, ни как проваленный.

**Забрать ход.** Кнопка <kbd>◀</kbd> под доской, клавиша <kbd>←</kbd> или свайп вправо
откатывают к позиции перед твоим последним ходом — снимается и ответ белых, и твой ход,
так что снова оказываешься перед выбором. <kbd>⏮</kbd> и <kbd>Home</kbd> отматывают
вариант к началу. Полезно, когда из позиции идут две книжные ветки и хочется посмотреть
вторую, или когда просто промахнулся мышкой.

На статистику откат не влияет: назад берутся только *принятые* ходы, а ошибка
засчитывается в момент неверного хода, когда фигура даже не встаёт на доску.
Стереть уже сделанную ошибку откатом нельзя.

**Что тренируем.** В настройке (кнопка в тренажёре, клавиша <kbd>T</kbd>) варианты
включаются и выключаются поштучно и главами, там же видна статистика. По умолчанию
выключены две группы — их помечает сборка, флаг `off` в данных:

* партии целиком — их не учат наизусть;
* линии, где плохой ход показан **за свою сторону** («Ловушка: 4…Kf6?»): просить
  повторить такой ход нельзя. Плохие ходы соперника наоборот остаются — их учатся
  наказывать. Чья сторона «своя», сборка берёт из `side` книги.

**Статистика** живёт в `localStorage` браузера (ключ `chessbooks.trainer.v1`), поэтому
переживает перезагрузку, но привязана к браузеру и не уезжает вместе с файлом.
По каждому варианту: сколько прогонов, сколько из них без ошибок, текущая серия чистых
прогонов. Значок в списке: `✓ 3/4` — выучен (две чистых подряд), `✕ 0/1` — последний
прогон с ошибкой, `• 1/3` — в работе, `—` — не пробовал. Чем хуже знаешь вариант,
тем чаще он выпадает: не пробованные и последние проваленные идут в 6–8 раз чаще
выученных. Кнопка «сбросить статистику книги» стирает всё по текущей книге.

## Известные ограничения и что делать дальше

* Комментарии Бладгуда оставлены на английском — это прямая речь автора из PGN,
  а не пересказ. Перевод не делался, чтобы не переврать.
* Книга Басмана разобрана по «Index of Variations» (стр. 171–172) и разделу
  «The Grob with White» (стр. 44–48). Вторая половина книги — «Гроб за чёрных»
  (1…g5 против 1.e4, 1.d4, 1.c4) — не разобрана; её можно добавить отдельной книгой
  со своим `side`. Оценок движка у неё нет: Stockfish на машине сборки не стоял,
  градусник показывает только книжный символ.
* Книги Москаленко и Гуфельда — **сканы без текстового слоя**. Ходы брались из «Индекса
  вариантов» и прочитанных вручную страниц, комментарии — с прочитанных страниц.
  Охват: Москаленко ~27 страниц из 308, Гуфельд ~20 из 333. Корнев — с текстовым слоем,
  разобраны части 1–2 (главы 1–8 из 16).
* Полезно прогнать сканы через OCR с русским языком (`ocrmypdf -l rus+eng`) — тогда
  книгу можно искать по тексту и добирать комментарии массово.
* Не сделано: главы 9–16 у Корнева; части «Из практики романтиков наших дней»
  у Гуфельда; сами партии (миттельшпили) у Москаленко, кроме двух разобранных.
* `run.py check` ловит только грубые ошибки записи (резкое падение оценки). Тихие
  неточности — перепутанный порядок ходов при той же оценке — он не увидит.
  Первый ход варианта проверка пропускает: Stockfish оценивает 1.g4 примерно
  в −1.3 за белых, и это не ошибка записи, а мнение движка о самом дебюте.
  У Бладгуда остаётся 55 срабатываний — там в главные линии вшиты реальные партии
  с реальными зевками; данные машинные, из PGN, и главные линии сверены с ним
  один в один.
* Проводник ходит только по правилам; произвольную расстановку фигур он не умеет.
  Превращение пешки всегда в ферзя.
* Тренажёр считает вариант выученным по двум чистым прогонам подряд — это не интервальное
  повторение, срок с прошлого раза не учитывается. Статистика лежит в браузере: другой
  браузер или режим инкогнито начнут с нуля.
* «Плохой ход за чёрных» тренажёр распознаёт по заголовку варианта. Если такой ход
  помечен только в комментарии, вариант придётся выключить руками.
* PDF-книг в репозитории нет (объём и авторские права): они лежат в `books/`,
  который в `.gitignore`.
