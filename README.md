# Шахматные книги → интерактивные приложения

Конвейер, который превращает шахматную книгу в самодостаточный HTML-файл:
доска, варианты по главам, комментарии, оценки Stockfish и проводник по позициям.
Интернет при работе приложения не нужен — библиотеки, фигуры и данные вшиты в файл.

Сборка одна: **все книги в одном файле** `dist/index.html` — вкладки книг сверху,
проводник и тренажёр работают сразу по всем книгам. Он же корень сайта.
Репертуар может быть и за чёрных, и за белых: поле `side` в `src/books.py` разворачивает
доску нужной стороной и определяет, за кого играет пользователь в тренажёре.

| id | книга | вариантов | ходов | комментариев |
|---|---|---|---|---|
| `alekhine` | А. Корнев, «Play the Alekhine Defence» (2019) | 50 | 1170 | 273 |
| `pirc` | В. Москаленко, «Защита Пирца-Уфимцева и Современная защита» (2016) | 62 | 1289 | 303 |
| `kid` | Э. Гуфельд, О. Стецко, «Искусство староиндийской защиты» (2017) | 31 | 621 | 119 |
| `grob` | М. Басман, «The Killer Grob» (1991) — за **белых** | 40 | 439 | 66 |
| `mygrob` | разбор 2940 собственных партий 1.g4 — за **белых** | 12 | 158 | 58 |
| `bloodgood` | К. Бладгуд, «The Tactical Grob» (2002) — за **белых** | 39 | 1213 | 290 |
| | **всего в объединённом файле** | **234** | **4890** | **1109** |

Книга `mygrob` устроена не как остальные: источник у неё не книга, а собственный архив
партий (`E:\Документы\_Dev\chess`) и его разбор. Каждый вариант доигран до позиции, где
я регулярно ошибаюсь, и продолжен **правильным** ходом — его и спрашивает тренажёр;
ход, который игрался на самом деле, лежит побочной линией на той же развилке. Поэтому
неправильных ходов отдельными вариантами в ней нет: тренажёр ищет сыгранный ход по всем
вариантам книги, и плохой ход, оформленный вариантом, перестал бы считаться ошибкой.

Оценки Stockfish (глубина 16) посчитаны и вшиты в файл: 5124 позиций главных
линий плюс 4490 позиций побочных. Побочные считаются отдельной командой и хранятся
по FEN (`cpsub_<book>.json`), а не по номеру хода: линии ветвятся, зато одинаковые
позиции из разных вариантов считаются один раз. Уникальных позиций на все книги —
7197, столько и лежит в кэше оценок.

## Быстрый старт

```bash
pip install chess            # python-chess
apt-get install -y stockfish # бинарник ложится в /usr/games/stockfish

python3 run.py build         # dist/index.html — все книги в одном файле
```

Полный цикл по одной книге:

```bash
python3 run.py gen   kid      # data/data_kid.json из src/_body_kid.py
python3 run.py eval  kid      # Stockfish по главным линиям -> data/cp_kid.json
python3 run.py gen   kid      # ещё раз: подтягивает cp в data
python3 run.py subs  kid      # Stockfish по побочным линиям -> data/cpsub_kid.json
python3 run.py gen   kid      # и ещё раз
python3 run.py build          # пересобрать приложение
python3 run.py check          # автопроверка на просмотры

python3 run.py all kid        # всё сразу
```

`STOCKFISH=/path/to/stockfish` — если бинарник лежит в другом месте.

### Кэш оценок

Оценки движка лежат в `data/evalcache.json` и ключуются позицией (FEN без счётчиков
ходов), а не вариантом. Кэш в репозитории, поэтому `eval`, `subs` и `all` спокойно
зовутся сколько угодно: Stockfish поднимается, только если нашлись позиции, которых
в кэше ещё нет. Полная пересборка всех пяти книг из готового кэша — пара секунд
вместо полутора часов счёта.

```bash
python3 run.py cache          # сколько позиций готово и сколько считать (движок не нужен)
python3 run.py seed           # сложить в кэш оценки из cp_*.json и cpsub_*.json
```

`cache` стоит звать перед долгим прогоном: он покажет, во что тот обойдётся. `seed`
восстанавливает кэш из уже посчитанных оценок, если файл потеряется.

Побочный эффект кэша: одна позиция теперь всегда получает одну оценку. Раньше при
лимите 0.9 с движок от запуска к запуску доходил до разной глубины, и одна и та же
позиция, встречаясь в разных вариантах, получала разные числа — у начальной их
набралось три десятка в пределах трети пешки. Теперь градусник не дёргается при
перестановке ходов.

## Публикация на GitHub Pages

`dist/` в репозитории нет — его собирает GitHub Actions. Обновление сайта = `git push`:
push в `main` запускает [.github/workflows/pages.yml](.github/workflows/pages.yml),
тот делает `python run.py build` и публикует `dist/`. Сборке не нужны ни Stockfish,
ни python-chess — только стандартная библиотека, данные книг уже лежат в `data/`.

Пересобрать без коммита: вкладка **Actions → Публикация на GitHub Pages → Run workflow**.

Настройка один раз:

```bash
git remote add origin https://github.com/<аккаунт>/chessbooks.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
Первый деплой поднимется через пару минут по адресу `https://<аккаунт>.github.io/chessbooks/`.

На сайте оказывается один файл — `index.html`, он же приложение.

## Структура

```
run.py                 единственная точка входа: gen / eval / subs / build / check /
                       cache / seed / all; здесь же кэш оценок (класс Evals)
src/
  books.py             заголовки книг и короткие имена вкладок
  _head.py             build() и add() — разбор ходов через python-chess
  _body_alekhine.py    ← ВСЁ СОДЕРЖИМОЕ КНИГИ: вызовы add(...) с ходами и комментариями
  _body_pirc.py
  _body_kid.py
  _tail_clean.py       постобработка: вехи оценок, подварианты, кликабельные ходы,
                       сортировка по главам, превью, флаг off (вне тренировки),
                       запись data_<book>.json
  scan.py              распознавание последовательностей ходов внутри текста комментариев
  pgn2body.py          PGN-книга -> _body_<id>.py (так сделана книга Бладгуда)
  template.html        шаблон приложения (плейсхолдеры __TITLE__, __BOOKS__, __JQUERY__ и т.д.)
data/                  data_<book>.json — готовые варианты; cp_<book>.json — оценки движка;
                       evalcache.json — кэш оценок по позициям, переживает сборки
vendor/                jquery, chess.js, chessboard.js, 12 SVG-фигур Cburnett
dist/                  готовые приложения (в гит не идут, собираются заново)
docs/                  заметки
.github/workflows/     сборка и публикация на GitHub Pages
```

В `__BOOKS__` уезжает список книг `[{id, short, h1, eyebrow, sub, credit, vars}]`.
Добавить четвёртую книгу — дописать её в `BOOKS` и положить `data_<id>.json`,
вкладка появится сама.

## Книга из PGN

Бладгуд пришёл не сканом, а базой партий: каждая запись PGN — вариант с авторскими
комментариями, вложенными вариациями и знаками. Разбирать такое глазами незачем:

```bash
python3 src/pgn2body.py books/tactical_grob.pgn > src/_body_bloodgood.py
```

Берутся только теоретические записи (тег `White` вида `Variation ...`); две с лишним
сотни партий целиком пропускаются. Знаки `!`/`?`/`!?` становятся пометками к ходу.

**Вложенные вариации не пересказываются текстом — они играются.** Каждая альтернатива
уезжает в `SUBS` и появляется кнопкой под доской (`▷ 4…Qc7`), которая проигрывает
линию ход за ходом. В комментарии остаётся только смысл: заголовок альтернативы и то,
что о ней сказал автор. Связки вроде «and if» без ходов рядом отсеиваются — они
бессмысленны. Полная выкладка ходов лежит под раскрывашкой «вся выкладка ходов»:
она никуда не делась, но по умолчанию не мешает.

Так средний комментарий занимает 165 пикселей вместо портянки на три экрана.
Первый заход был именно портянкой — доска для того и есть, чтобы линии смотреть,
а не читать. Дальше файл живёт как обычный `_body_*.py`, его можно править руками.

Комментарии переводятся на русский словарём [src/grob_ru.py](src/grob_ru.py):
`EXACT` для живых фраз целиком, `PHRASES` для повторяющихся кусков (из 530 разных
комментариев больше половины — короткие вердикты вроде «with advantage to White»).
Имена, турниры и годы в ссылках на партии не переводятся. Отчёт о непокрытом:

```bash
python3 src/grob_ru.py books/tactical_grob.pgn
```

## Как добавить вариант

В `src/_body_<book>.py`:

```python
add("ид_варианта", ГЛАВА, "Заголовок", "³", "³ у чёрных чуть лучше",
 "e4 d6 d4 Nf6 Nc3 g6 f4 Bg7",          # ходы через пробел, SAN
 {"4.f4": "Комментарий к этому ходу.",   # ключ — номер и ход как их печатает движок
  "4...Bg7": "И к этому."})
```

Ключ комментария (`"4...Bg7"`) сверяется со списком, который генерирует python-chess.
Если промахнулся — `gen` падает и печатает **все** доступные ключи варианта: просто
скопируй нужный. Нелегальный ход тоже сразу валит сборку — это главная защита от
ошибок при переносе с бумаги.

Необязательные поля в конце файла книги:

* `EVALS = {"ид": {"9.Nxe5": "µ"}}` — вехи книжной оценки (символ в градуснике до
  появления движковых оценок).
* `SUBS  = {"ид": {"8...e5": [("подпись", "Nxe5 Nd4 Qd3", "after")]}}` — побочные линии,
  проигрываемые на доске; `"before"` = от позиции перед указанным ходом.

Кроме того, `scan.py` сам находит последовательности ходов **внутри текста** комментария,
проверяет их на легальность и делает кликабельными. Различает два вида: обычную линию
(ходы чередуются) и «расстановку» — план одной стороны, где ходы соперника пропускаются
через null-move.

## Что умеет приложение

* вкладки книг сверху, клавиши <kbd>1</kbd>…<kbd>9</kbd> — переключение между защитами;
* три режима: чтение варианта, проводник по позициям и тренажёр;
* доска (chessboard.js + chess.js), развёрнутая со стороны чёрных, свайпы и стрелки;
* выбор варианта списком по главам + стрелки перехода между вариантами;
* комментарии с защитой от пропуска: вспышка, вибрация, счётчик и плашка
  «пропущено N — вернуться» (счётчик прочитанного свой у каждой книги);
* градусник Stockfish (глубина 16, посчитано заранее и вшито в файл);
* с телефона фигуры ходят касаниями: тап по фигуре — подсветятся её поля, тап по полю —
  ход; повторный тап снимает выбор. Мышью работают оба способа одновременно, без всяких
  переключателей режимов: и перетаскивание, и два щелчка (см. «Почему щелчок мышью
  приходится ловить в onDrop» ниже);
* кликабельные побочные линии прямо в тексте комментариев;
* **проводник**: свободно двигаешь фигуры, приложение показывает книжные продолжения
  из этой позиции с числом вариантов и список совпадающих линий с переходом в них —
  **сразу по всем книгам**. После 1.e4 видно `Nf6 50` (Алехин), `d6 50` и `g6 9` (Пирц
  и Современная), после 1.d4 — староиндийские линии. Клик по совпадению перекидывает
  в нужную книгу и на нужный ход. Поиск по FEN, поэтому перестановки ходов ловятся сами.
* **тренажёр** — см. ниже.

### Раскладка на ПК

Слева доска, справа комментарий, кнопки режимов и полоса повторений — больше в правой
колонке ничего нет. Выбор варианта и строка «вариант N из M» остались наверху во всю
ширину, как и были. Раньше комментарий лежал под доской и уезжал за нижний край экрана —
на ноутбуке его приходилось выискивать прокруткой, ради чего всё и переделано.

Обе колонки — единый блок по центру, а не враспор по краям монитора: ширина правой колонки
ограничена (340–520px, по 45% ширины блока), и `justify-content:center` держит пару
посередине. На 1366 и на 1920 поля слева и справа одинаковые.

Таблицы «все ходы варианта» на ПК нет, полоски со стрелками — тоже: ходы листают стрелки
клавиатуры, доску разворачивает <kbd>F</kbd>. Всё это место отдано комментарию. В проводнике
той же панелью показывается список совпадающих вариантов — это не история ходов, а смысл
режима, — он встаёт под комментарием, и оба прокручиваются внутри себя. На телефоне таблица
никуда не делась и по-прежнему свёрнута по умолчанию.

Размер доски считает `fitDesk()` по высоте окна, а не CSS: высота шапки зависит от длины
описания книги, формулой это не выразить. Функция раздаёт четыре переменные — ширину левой
колонки, ширину и высоту правой, потолок списка совпадений — и сама зовёт `board.resize()`,
потому что высоту доске ставит chessboard.js, а `ResizeObserver` срабатывает только при
отрисовке кадра. Обратной связи нет: меряем от верха левой колонки, а он от размера доски
не зависит. На экранах ниже 820px шапка и подвал дополнительно поджимаются — иначе доске и
комментарию остаётся слишком мало.

Замеры (доска одинакова в книге, тренажёре и проводнике):

| экран | доска | комментарий | вертикальная прокрутка |
|---|---|---|---|
| 1366×768 | 369×370 | 493×310, без прокрутки читается 81% комментариев | нет, вместе с подвалом |
| 1920×1080 | 520×514 | 493×576, без прокрутки читается 95% комментариев | нет, вместе с подвалом |

Длина комментариев по всем книгам: медиана 78 символов, три четверти короче 166, девять
десятых короче 421. Медиана и верхняя четверть читаются целиком на обоих экранах; хвост
длиннее 400 символов прокручивается внутри своей области, страницу не растягивая.

Мобильная раскладка не тронута: элементы лежат в тех же координатах с точностью до пикселя,
что проверено сравнением со сборкой до правки. Достигается это тем, что правая колонка на
узком экране растворяется (`display:contents`), а прежний порядок блоков восстанавливается
через `order`.

## Тренажёр

Кнопка «🎓 Тренажёр» или клавиша <kbd>T</kbd>. Приложение играет за белых по одному
из вариантов книги, ты отвечаешь за чёрных перетаскиванием фигур. Заголовок варианта
на время прогона скрыт — он открывается в конце.

**Развилки.** Из многих позиций книга даёт не один ответ (в Пирце таких развилок 20).
Если сыграть ход из другой линии — это не ошибка: фигура возвращается, а тренажёр
пишет «✓ ход правильный, он ведёт в вариант «…». Но сейчас мы тренируем другой».
Прогон остаётся на начатом варианте: иначе он растекался бы по всей книге.

Исходы хода:

| что сыграл | реакция | ошибка? |
|---|---|---|
| ход целевого варианта | идём дальше | нет |
| ход есть в книге, но в другом варианте | «✓ правильный, но тренируем другой», фигура назад | нет |
| ход по правилам, но в книге его нет | «✕ такого хода нет в репертуаре» | да |
| ход не по правилам | «так не сходить», фигура возвращается | нет |
| забрал ход назад | откат к прошлой развилке | нет |

Кнопка «Показать ход» играет книжный ответ за тебя и засчитывает ошибку,
«Не знаю, дальше» закрывает вариант как непройденный и берёт следующий.
«Открыть в книге» (клавиша <kbd>B</kbd>) в любой момент выходит из тренажёра прямо
на текущей позиции текущего варианта — прогон при этом не засчитывается ни как
пройденный, ни как проваленный.

**Забрать ход.** Кнопка <kbd>◀</kbd> под доской, клавиша <kbd>←</kbd> или свайп вправо
откатывают к позиции перед твоим последним ходом — снимается и ответ белых, и твой ход,
так что снова оказываешься перед выбором. <kbd>⏮</kbd> и <kbd>Home</kbd> отматывают
вариант к началу. Полезно, когда из позиции идут две книжные ветки и хочется посмотреть
вторую, или когда просто промахнулся мышкой.

На статистику откат не влияет: назад берутся только *принятые* ходы, а ошибка
засчитывается в момент неверного хода, когда фигура даже не встаёт на доску.
Стереть уже сделанную ошибку откатом нельзя.

**Что тренируем.** В настройке (кнопка в тренажёре, клавиша <kbd>T</kbd>) варианты
включаются и выключаются поштучно и главами, там же видна статистика. По умолчанию
выключены две группы — их помечает сборка, флаг `off` в данных:

* партии целиком — их не учат наизусть;
* линии, где плохой ход показан **за свою сторону** («Ловушка: 4…Kf6?»): просить
  повторить такой ход нельзя. Плохие ходы соперника наоборот остаются — их учатся
  наказывать. Чья сторона «своя», сборка берёт из `side` книги.

**Статистика** живёт в `localStorage` браузера (ключ `chessbooks.trainer.v1`), поэтому
переживает перезагрузку, но привязана к браузеру и не уезжает вместе с файлом.
По каждому варианту: сколько прогонов, сколько из них без ошибок, текущая серия чистых
прогонов. Значок в списке: `✓ 3/4` — выучен (две чистых подряд), `✕ 0/1` — последний
прогон с ошибкой, `• 1/3` — в работе, `—` — не пробовал. Чем хуже знаешь вариант,
тем чаще он выпадает: не пробованные и последние проваленные идут в 6–8 раз чаще
выученных. Кнопка «сбросить статистику книги» стирает всё по текущей книге.

## Интервальные повторения в тренажёре

Отдельного режима карточек по позициям нет — расписание навешено на сам тренажёр.
**Единица повторения — вариант целиком**: прогон от начала до конца. Ключ варианта — хэш
его списка ходов, поэтому переименование варианта или переезд в другую главу прогресс не
сбрасывают, а правка самих ходов начинает счёт заново (это уже другое упражнение).

**Оценка выводится из всего прогона, а не из одного хода.** Чисто и быстро (меньше четырёх
секунд на свой ход) — «легко», чисто — «нормально», одна ошибка — «трудно», две и больше
или подсмотренный ответ — провал. Дальше — ступени изучения, а после них обычный SM-2
с доработками: лёгкость, растущие интервалы, разброс, чтобы варианты не слипались.

**Ступени изучения: час → восемь часов → сутки.** Новый вариант не выходит на дневную
лесенку сразу. Сперва он возвращается через час, потом через восемь часов, потом через
сутки, и только пройдя все три чисто выпускается на интервал 2 дня (3 дня, если последний
прогон был «легко»). Смысл в том, что за один вечер вариант успевает всплыть трижды с
растущими промежутками — это и есть то, что переводит линию из «только что смотрел» в
«помню назавтра». **Провал на любой ступени откатывает на первую**, то есть на час.

Ступени не конфликтуют с правилом «зачёт только по сроку»: у ступени тоже есть срок, и
пока он не наступил, прогон идёт как практика. Именно поэтому срок теперь хранится меткой
времени с точностью до часа, а не номером дня, — днями час и восемь часов не выразить.

**Провал выпускника** (вариант уже на дневной лесенке) уводит на короткое переучивание:
час → восемь часов, и потом интервал **40% от прежнего**, но не меньше суток. Полностью в
начало гнать нечестно — вариант уже был знаком, забылся один раз, а не никогда; но и
возвращать прежний интервал нельзя, иначе провал ничего не стоит. Пример: вариант стоял на
восьми днях, провалился — переучивание за вечер и следующий срок через три дня.

Пока вариант на ступенях, его вклад в процент почти нулевой (интервал меньше суток),
и в сводке он числится «в работе». Процент растёт только после выпуска.

Почему SM-2, а не FSRS: вся сила FSRS в подгонке параметров под лог повторений конкретного
человека. Лога нет; на холодном старте FSRS с дефолтными весами работает примерно как
SM-2, а кода и способов ошибиться заметно больше — в файле, который целиком инлайнится в
один HTML без сборки и тестов. В состоянии хранится всё для будущей подгонки: повторы,
провалы, интервалы, время прогона.

**Лесенку интервалов двигает только повтор по сроку.** Тренироваться чаще расписания
можно и полезно, но досрочный прогон (срок повтора ещё не подошёл) идёт как практика и
только: ни интервал, ни лёгкость, ни процент от него не двигаются. Иначе за один вечер
вариант уезжает на три недели вперёд, ничего не доказав — так и было до этой правки:
три прогона по полчаса поднимали интервал 2 → 6 → 19 дней, пока срок ни разу не наступал.

Отдельного исключения для «дня знакомства» не понадобилось: у нового варианта срок стоит
на «сейчас», поэтому первый прогон засчитывается. Доучка сразу после ошибки в зачёт не
идёт — провал ставит срок на час вперёд, и это ровно то, чего мы хотим: переигрывание по
горячим следам ничего не доказывает.

Чтобы при этом не казалось, что тренируешься весь день, а не меняется ничего, в полосе
над доской стоит счётчик за сегодня: «сегодня 8 прогонов, в счёт 3». А когда тренажёр
берёт вариант досрочно, там же пишется «досрочно — срок ещё не подошёл, расписание не
двинется», и то же самое повторяется в итоге прогона.

**Повтор по горячим следам не засчитывается.** Переигрывать вариант сразу после ошибки
полезно и никто не мешает, но это massed practice: он показывает короткий след в голове,
а не память. Поэтому прогон, начатый в течение **десяти минут** после последнего
засчитанного, идёт как практика и только: ни интервал, ни лёгкость, ни серия чистых от
него не двигаются, процент не растёт. Настоящий зачёт вариант получает со следующего
прохождения, разнесённого по времени. Окно работает в обе стороны — повторный провал по
горячим следам тоже не штрафует второй раз. Статус видно заранее: в полосе над доской
пишется «повтор по горячим следам — этот прогон в счёт не пойдёт», и то же самое
повторяется в итоге прогона.

**Порядок вариантов** и потолок: потолка нет, тренироваться можно сколько угодно подряд.
Следующий вариант выбирается заново каждый раз: сперва просроченные (вперёд самые
перележавшие, просрочка считается относительно собственного интервала), потом подошедшие
сегодня (сначала те, где были провалы), потом ни разу не пройденные по весу (частота ошибки
в партиях — см. `PRIO` в `_body_mygrob.py`), потом ближайшие к забыванию. Последние
показанные придерживаются, так что один вариант не идёт дважды подряд.

**Процент выученного** считается по вариантам книги и стоит над доской. Полностью выученным
вариант считается при интервале 21 день (порог зрелости из Anki). Но считать только зрелые
нечестно к первым неделям, поэтому каждый вариант даёт свою долю пути: 21 день и больше —
единица, семь дней — треть, ни разу не пройденный — ноль; процент это среднее по книге.
Растёт после каждого чистого прогона, падает сразу при провале. Рядом сырой счёт: сколько
держится уверенно, сколько в работе, сколько не пройдено, сколько ждёт повтора.

**Срок пишется по-человечески**, а не датой: «можно повторять сейчас», «вернётся через
час», «вернётся сегодня утром / днём / вечером», «вернётся завтра», «вернётся через
5 дней». Часовые ступени иначе выглядели бы как «вернётся сегодня» и не отличались бы
друг от друга.

**Несколько верных ходов на развилке.** Если книга из текущей позиции играет и другой ход —
в другом варианте или приемлемой побочной линией, — это не ошибка: тренажёр говорит, чей
это ход, и просит сыграть по текущей линии. Совпадение считается **по позиции**, а не по
совпадению ходов вообще: иначе привычная ошибка (7.Nc3 в ловушке h4) проходила бы как
«правильно, другая линия». Приемлемость побочной линии определяется флагом `alt`/`bad` в
книге, знаками автора в подписи (`?` — плохо, `!` и `!?` — играбельно) или оценкой движка.

**Строка «почему»** после каждого ответа объясняет исход: «книжный ход, но из варианта
«…»», «книга допускает и его: «…»», «книга разбирает этот ход как ошибку: «…»», «из этой
позиции такого хода в книге нет», а в конце прогона — как это повлияло на интервал.

**Где лежит прогресс.** В `localStorage`, ключ `chessbooks.srs.v1`, разложенный по книгам;
переноса между устройствами нет. Старая статистика тренажёра (чистые прогоны и серии)
используется как затравка интервалов, чтобы уже пройденное не начиналось с нуля.

## Известные ограничения и что делать дальше

* Перевод Бладгуда — словарный, а не литературный: он хорошо ложится на формульные
  вердикты и хуже на длинные рассуждения. Спорные места видно в оригинале — он лежит
  в `books/tactical_grob.pgn`.
* Книга Басмана разобрана по «Index of Variations» (стр. 171–172) и разделу
  «The Grob with White» (стр. 44–48). Вторая половина книги — «Гроб за чёрных»
  (1…g5 против 1.e4, 1.d4, 1.c4) — не разобрана; её можно добавить отдельной книгой
  со своим `side`. Оценок движка у неё нет: Stockfish на машине сборки не стоял,
  градусник показывает только книжный символ.
* Книги Москаленко и Гуфельда — **сканы без текстового слоя**. Ходы брались из «Индекса
  вариантов» и прочитанных вручную страниц, комментарии — с прочитанных страниц.
  Охват: Москаленко ~27 страниц из 308, Гуфельд ~20 из 333. Корнев — с текстовым слоем,
  разобраны части 1–2 (главы 1–8 из 16).
* Полезно прогнать сканы через OCR с русским языком (`ocrmypdf -l rus+eng`) — тогда
  книгу можно искать по тексту и добирать комментарии массово.
* Не сделано: главы 9–16 у Корнева; части «Из практики романтиков наших дней»
  у Гуфельда; сами партии (миттельшпили) у Москаленко, кроме двух разобранных.
* `run.py check` ловит только грубые ошибки записи (резкое падение оценки). Тихие
  неточности — перепутанный порядок ходов при той же оценке — он не увидит.
  Первый ход варианта проверка пропускает: Stockfish оценивает 1.g4 примерно
  в −1.3 за белых, и это не ошибка записи, а мнение движка о самом дебюте.
  У Бладгуда остаётся 55 срабатываний — там в главные линии вшиты реальные партии
  с реальными зевками; данные машинные, из PGN, и главные линии сверены с ним
  один в один.
* Проводник ходит только по правилам; произвольную расстановку фигур он не умеет.
  Превращение пешки всегда в ферзя.
* Значок «выучен» в списке вариантов по-прежнему ставится по двум чистым прогонам подряд —
  это грубая метка, не имеющая отношения к расписанию; настоящий прогресс показывает
  процент над доской. Всё состояние лежит в браузере: другой браузер или режим инкогнито
  начнут с нуля.
* «Плохой ход за чёрных» тренажёр распознаёт по заголовку варианта. Если такой ход
  помечен только в комментарии, вариант придётся выключить руками.
* PDF-книг в репозитории нет (объём и авторские права): они лежат в `books/`,
  который в `.gitignore`.
